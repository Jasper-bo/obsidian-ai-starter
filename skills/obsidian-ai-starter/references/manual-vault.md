# 按选定方案用文件工具建库

先完成 `knowledge-design.md` 的访谈与结构设计。用当前 Agent 的文件工具按已选方案在独立文件夹创建目录，已有 Vault 复用原位置。普通个性化建库不需要 Python 或固定目录脚本。没有目标文件夹读写能力时，交接目录树与具体创建步骤，并保留“尚未创建”的状态。

创建用户习惯命名的首页，链接实际存在的主题、项目或常用入口，说明新资料怎样入库、怎样找到及复用。记录目录职责与一个真实任务示例；同名文件先读取，仅补充需要的信息。保留用户已有内容，不为适配示例强行重命名。

来源笔记记录标题、原始 URL 或原文件路径、收录日期、正文及是否 OCR。其他笔记随用途确定：选题记录问题/受众/角度/依据，学习笔记连接课程和未解决问题，知识卡记录结论/依据/适用范围。个人判断标记为推断，生成结论链接回来源。

在方案的系统记录区域保存 `建库方案.md` 与 `搭建记录.md`，首页可链接到它们。模板与附件目录仅在当前流程需要时创建，不要求统一编号或统一目录名。

Obsidian 自己管理 `.obsidian` 配置。不需要手动写插件设置；若方案设附件目录，在 Obsidian 设置中选择对应位置。

对照选定方案检查实际目录与笔记：首页指向的文件存在，系统记录可找到，样例入库路径符合用户偏好，没有擅自添加另一套固定布局。使用宿主文件搜索或包内只读 search 定位关键词，排除模板/系统记录后读原文再回答。个性化库不用固定布局的 doctor 作为成功条件。

用户明确选择通用资料整理模板时，才可创建 `00-收件箱 / 10-来源 / 20-知识卡 / 30-主题 / 40-输出 / 90-模板 / 99-系统 / 附件`，并用包内 init/doctor。这一方案不应因脚本现成而被自动优先选择。
