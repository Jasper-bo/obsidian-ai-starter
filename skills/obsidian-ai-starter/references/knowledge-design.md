# 建库前的需求访谈与结构设计

先了解资料如何被使用，再决定它放在哪里。职业或行业只是线索，用户的实际任务与维护习惯才决定结构。沿用上下文已经明确的答案；每轮聚焦一个问题，不把下面的清单一次发成问卷。

## 如何开始

没有背景时问：“你主要想用这个知识库做什么？比如做内容、工作项目、学习，或者整理平时收集的资料。”

用户回答“我是自媒体”后，可问：“你希望它先帮你解决哪一件事：积累选题、找素材写稿，还是复盘已发布内容？”优先追问他选中的用途；内容形式会影响方案时再了解他做视频、图文还是其他内容。已知只做某一项时不问其余项。

再从答案中补齐有影响的缺口：

- **实际任务**：希望输入什么、最后拿到什么；例如从文章摘出可用案例、从会议资料找到决策、从课程笔记找到不懂的问题。
- **已有资料**：类型、规模、现在放在哪里，是否已有分类；能直接检查的文件不反复让用户描述。
- **组织偏好**：按主题查找、按项目推进、按创作/学习流程，或少分类直接搜索。用用户熟悉的词解释，不要求懂 PARA、Zettelkasten 等术语。
- **维护习惯**：用户会持续写笔记，还是更愿意只放资料、让 AI 整理；希望从一个首页进入还是习惯左侧文件夹。

无需固定问满几轮。信息足以决定结构就输出方案；尚不清楚时再问能区分候选方案的那一个问题。只知道“自媒体”尚不足以推定平台、变现方式、发布流程或复盘需求。

## “风格”可以怎样选

| 用户偏好 | 适合的组织方式 | 设计重点 |
| --- | --- | --- |
| 少操作，放进去以后能找 | 简单资料区 + 主题入口/搜索 | 少量大类；AI 帮助摘要、关联与检索 |
| 围绕主题长期积累 | 主题目录或主题索引 | 相同主题的来源、观点、问题可以连起来 |
| 经常围绕明确任务交付 | 项目或内容条目 | 一项任务有自己的目标、材料、过程、结果 |
| 日常工作有固定先后步骤 | 工作流程 + 常用素材 | 减少文件来回搬动，状态尽量在项目记录中表达 |

这些方式可以组合。例如自媒体按主题积累素材，用单独的内容项目记录选题、脚本、发布和复盘；同一份原始素材通过链接复用，无需复制到每个项目。

## 自媒体示例（必须按回答裁剪）

场景：用户做 AI 科普短视频，主要卡在选题和找素材，愿意按内容项目管理制作。可提出：

```text
我的内容工作台/
├── 首页.md                 # 最近在做什么、常用入口
├── 随手收集/               # 暂时来不及归类的内容，确有需要才建
├── 主题资料/               # 按其实际领域分主题；每份资料保留出处
├── 选题/                   # 问题、受众、角度、可用依据
├── 内容项目/               # 一条内容串起脚本、素材引用和制作记录
├── 可复用素材/             # 案例、自己的经验、常用图等，按实际需要细分
└── 系统/                   # 建库方案、搭建记录及所需模板
```

不自动建立“商业化”“客户”“团队”“发布数据”等用户没有提到的区域。确实需要复盘时，可在同一内容项目记录发布数据和判断，再将可复用经验链接出来；无需默认再加一个与项目重复的完整目录。

如果同一位自媒体用户主要是读文章积累观点、希望极简，则可只提出 `首页.md / 主题资料 / 我的想法 / 内容草稿 / 系统`。身份相同也可以有不同结构。

## 其他用途示例

- 学生备考：按所学课程组织，按需求链接知识点、例题、错题与未解决问题；用户不做刷题就不创建错题区。
- 研究阅读：按研究问题串联文献、证据、阅读记录和输出；区分作者原结论与自己的推断。
- 工作项目：项目内放目标、会议决策、资料和交付；共享资料单独保存并链接，避免项目间重复拷贝。
- 通用资料整理：用户明确喜欢收件箱、来源、知识卡和主题地图时，可用包内固定模板脚本。它是一个可选方案。

## 方案应该怎样呈现

给出一句用途描述、文本目录树、每个主要区域的职责，以及一个来自用户任务的流转例子。说明新资料放哪里、怎样找、怎样复用。命名使用用户熟悉的词；目录数量和层级按实际资料需要，不提前铺满空文件夹。

把偏好与方案写进所选系统区域的 `建库方案.md`，至少包括身份/用途、优先任务、资料范围、组织偏好、选定目录及原因、以后出现什么需求再扩展。输出的目录树是可调整方案，不宣称某一结构适合所有同职业用户。

已有建库授权且用户的选择已充分明确时，展示方案后直接创建。两种方案会明显改变维护方式、而用户尚未表达偏好时，先让他选一种；不把问题改写为笼统的“要不要继续”。已有库仅做差异建议，未经迁移授权保留原位置。
